What this is solving

The vibe coding workshop is the on ramp: how software actually gets built, GitHub as the audit trail for agent written code, v0 and Vercel as the build and deploy loop, and directing agents by specification instead of syntax. The production workshop assumes all of that and spends the day on agent harnesses, context engineering, MCP and A2A, skills, memory, agent patterns, governance, security, sovereignty, tokenomics and ethics.

Your gap is not the git and CI/CD half. With an AWS, GCP, Terraform, Kubernetes and DevSecOps background, most of Mark's morning is review for you. The genuinely new material is the agent specific half, plus one habit that workshop teaches well and most engineers skip: treating the pull request as the checkpoint where a human stays in charge of machine written code.

So this track compresses the vibe coding content into five sessions that you ship something real with, then spends the remaining sixteen on the production syllabus, item by item, with your own code and your own homelab.

How it is built

  • 21 sessions, the full track, nothing trimmed, about 33.5 hours, scheduled into a fixed daily block of roughly 6 hours of ATO and 2 hours of Verily, Monday through Friday, with the rest on Saturday.
  • Every session ends in a deliverable committed to one repo. No passive reading sessions.
  • One through line project carries all 21 sessions, so by October 19 you have a deployed app, a working MCP server, an eval suite and a threat model on the same codebase.
  • Progress is saved in this browser. Check boxes as you go, take notes in each session, come back to it.

The through line project

Pick one and keep it for all 21 sessions. The workshop prerequisites ask you to bring an idea, and small and real beats big and vague. The recommended one, because it uses what you already know and doubles as an sgt7 portfolio piece:

Cloud Posture Brief. Feed it a set of cloud misconfiguration findings. It returns a prioritized remediation brief for a non technical owner, with each finding mapped to the CIS benchmark item and the NIST 800-53 control family it touches, plus an effort estimate and a suggested fix. A web front end for the brief, an agent behind it, an MCP server exposing the control catalog and finding store as tools.

It works for this track because it needs real tools (not a chatbot), it has parts that must be deterministic (control ID mapping, severity math) and parts that are legitimately probabilistic (prose, prioritization, explanation), and it is a thing a small business would actually pay for.

Questions worth the room

A one day workshop with a practitioner is worth more for what you ask than what you are told. These are written so they cannot be answered with a slide. Check off the ones you get answered, and write the answer in the box under each.

The day before

Your ninety second answer

You will be asked what you are working on, by the instructor or by the person next to you. Have this ready and rehearsed, it is the single highest return thing you can prepare. Structure:

  1. Who you are in one line. Founder of sgt7, cloud security and DevSecOps for small and mid sized businesses in the Triangle, Army veteran, AWS and GCP background.
  2. What you built. The Cloud Posture Brief, what it does, the fact that it has an MCP server and an eval suite behind it.
  3. The specific thing you are stuck on or unsure about. This is the hook. People answer a concrete problem, they do not answer "tell me about agents."

Write it here, then say it out loud three times.

The week after

  • Day 1. Transcribe your notes into notes/ato-2026-debrief.md while they still mean something. Anything you wrote as a question, mark it answered or still open.
  • Day 2 to 3. Apply one change to the capstone from what you learned. One, not five. Commit it so the repo shows the workshop mattered.
  • Day 4 to 5. Write the public version: a post on what actually changed in agent engineering practice in 2026, using your own repo as the example. This is sgt7 marketing that does not read like marketing.
  • Day 6 to 7. Turn the capstone into a service page. An agent readiness assessment for an SMB is a sellable two week engagement: threat model, identity and least privilege review, eval harness, a runbook.
  • Follow up with the RDU AI Meetup, which Mark Hinkle co founded. Local room, 1,800 plus people, same crowd as the conference.
